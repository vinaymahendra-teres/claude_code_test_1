# Mode toggles — research & scope

_2026-05-24 · for Tiered Cake Company app_

## Why this is needed

The app's surface area has crept up: 10+ modules, a bottom nav of five, a More sheet with seven more entries, plus a Tweaks sheet. A solo baker rarely needs all of it at once — what's relevant at 6 AM (oven, stock, schedule) is different from what's relevant at 9 PM (P&L, balance due, scheduling tomorrow). Showing everything always is noise.

## The mental model

A **mode is a hat the baker is wearing right now**. Four hats:

| Mode | When | What it surfaces |
|------|------|------------------|
| **Planning & setup** | Menu changes, new recipe trials, restock runs | Recipes, Inventory, Tools (conversions, scaling) |
| **Marketing & CRM** | DMs, campaigns, birthdays, taking new orders | Customers, Marketing, Inbox |
| **Operations** | Active baking days — the default | Bakes (schedule), Kitchen (timers), Orders fulfilment |
| **Finance & accounting** | End-of-day, end-of-month, GST filing | Books (P&L/Tx/Tax), Financing, expenses |

## Research notes

Modes are a tested pattern in productivity software:
- **Notion** has Workspace switcher (per-context).
- **Apple Reminders / Calendar** have "lists" that filter the view.
- **Toggl / RescueTime** have project contexts.
- **Asana** has My Tasks vs Projects vs Inbox modes.

What unites the winners: the mode is **visible but not aggressive** (a pill or chip, not a screen-wide takeover), changes are **immediately reversible**, and the modes match **how the user mentally segments their day**, not how the app's data model is structured.

What kills mode designs: hiding things so aggressively that users can't find them when they need them. Mitigation: every module remains reachable via the More menu in every mode, but reordered so the active-mode items are at the top.

## What changes per mode

### Bottom nav (always Home + Orders + More, plus 2 mode-specific)

```
Planning   → Home · Orders · Recipes  · Inventory · More
Marketing  → Home · Orders · People   · Marketing · More
Operations → Home · Orders · Bakes    · Kitchen   · More
Finance    → Home · Orders · Books    · Financing · More
```

Rationale: **Home** and **Orders** are the universal spine — every mode touches them. The middle two slots flex.

### Home quick actions (the 4-button strip below the revenue card)

```
Planning   → New order · Scale  · Stock     · Recipes
Marketing  → New order · Campaign · Inbox    · People
Operations → New order · Timers · Plan week · Stock
Finance    → Expense   · Order  · Books     · Cashflow
```

### More menu (full list, but reordered)

The mode's "primary" modules float to the top of the More sheet; everything else stays accessible below.

## What stays mode-agnostic

- The phone shell (status bar, home indicator, notch).
- The persistent timer peek (a running timer matters in any mode).
- The Tweaks panel (always reachable via gear).
- The mode pill itself (always visible on Home so the user can switch).

## The toggle UI

A small **mode pill** sits in the Home header, right beside the date row. It shows `Operations ↕` (or the current mode). Tap → bottom sheet listing the four modes as large cards with a one-line description and a colored indicator. Selecting one switches immediately and dismisses the sheet.

The choice persists in localStorage (`tieredcake-mode`).

Default mode on first launch: **Operations** — that's the highest-frequency state for an active bakery.

## What's intentionally NOT in this iteration

- **Per-mode home section visibility** — would require rewriting the Home screen to be section-driven. Useful but bigger than this slice.
- **Mode-tinted accent colors** — explored on paper, dropped as gimmicky. Palettes belong in Tweaks.
- **Auto-mode by time-of-day** — `if 6am-10am, mode=operations` is plausible but presumptuous. Skip until users ask for it.
- **Mode-specific notifications** — out of scope without a real notification system.

## Open questions

- Should the mode pill also appear on other screens (Bakes, Orders, etc.) or only on Home? **Decision: only Home for now, to keep the chrome clean. The bottom-nav already communicates the mode implicitly.**
- Should "Tweaks" be considered a mode item? **No — it's settings, not work.**
